## 기록 내역

## [2026-09-24] HWPX 압축 파일 취약점 사전 대비 (Security Hardening)
- **증상**: HWPX 문서는 내부에 Zip 압축된 XML을 포함하므로, 악의적인 Zip Slip(상위 경로 순회) 및 XXE(외부 엔터티 참조) 공격에 노출될 수 있음.
- **원인**: 표준 `xml.etree.ElementTree`는 외부 엔터티 및 DTD 공격을 방어하지 않으며, `zipfile.extract`는 상대경로(`../`)를 필터링하지 않으면 임의 디렉터리에 파일을 쓸 수 있음.
- **해결**:
  1. HWPX 내부 파일을 직접 디스크에 풀지 않고 메모리 상(`zipfile.read()`)에서만 읽어 처리.
  2. XML 파서로 표준 모듈 대신 `defusedxml.ElementTree`를 강제 사용.
- **재발 방지**: HWPX 및 Office OpenXML 파싱 시 디스크 파일 압축 해제를 금지하고 메모리 스트림 + `defusedxml` 원칙을 고수함.

## [2026-09-24] Windows 환경 PowerShell 및 파일 인코딩 규칙
- **증상**: 텍스트 파일 변환 및 PowerShell 스크립트 실행 시 한글 문자열이 깨지는 현상(CP949 vs UTF-8 충돌).
- **원인**: Windows 기본 환경에서 인코딩을 명시하지 않으면 시스템 로캘(CP949)로 읽혀 UTF-8 파일이 손상됨.
- **해결**: Python 파일 I/O 및 파서에서 `encoding="utf-8"`을 명시하고, 파일 인코딩 판별 시 `charset-normalizer`를 통해 CP949와 UTF-8을 안전하게 자동 감지함.
- **재발 방지**: 모든 텍스트 처리 모듈에서 인코딩 매개변수를 생략하지 않는다.

## [2026-09-24] PowerShell 스크립트 내 인라인 코드 변수 확장 버그
- **증상**: `harness.ps1`에서 `python -c "..."`로 파이썬 코드를 실행할 때 `name 'pdf_files' is not defined` 에러 발생.
- **원인**: PowerShell의 큰따옴표(`"`) 내 문자열은 `$변수명`을 파워쉘 변수로 치환하는데, `$pdf_files`를 빈 값으로 치환하여 파이썬 코드가 깨짐.
- **해결**: 인라인 스크립트를 하네스 내부에 문자열로 묻어두지 않고, 독립된 스모크 테스트 스크립트(`tests/smoke_test.py`)로 분리하여 실행.
- **재발 방지**: 하네스나 쉘 스크립트에서 파이썬 코드를 실행할 때는 인라인 문자열 대신 별도 `.py` 파일로 분리하여 작성한다.
